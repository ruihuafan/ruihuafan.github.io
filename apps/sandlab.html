sandlab ▓▒░

A falling-sand cellular automaton in one HTML file, inspired by Max Bittker's sandspiel — but pared down to a living world. There are just 12 elements, and nearly all of them are there to feed one closed ecosystem. Draw with the mouse, then watch it run. Pick any element on the right and its tuning sliders appear; press api rules under them and that element's behavior is plain JavaScript you can rewrite live.

The cast. Rock is inert bedrock (and the world's edge). Sand is loose mineral ground. Water is the resource everything runs on, and a Spring renews it — the one input to the whole system, this world's equivalent of sunlight. Exposed water also evaporates into Vapor, which drifts up, rides the sky a while, then condenses back as rain — so the weather itself is part of the water cycle. Plants are the producers: they need a footing of sand or soil and water within reach, and their color shows how hydrated they are. Grazers (teal) eat plants; Predators (pink) eat grazers; both keep energy in rb, breed from a surplus, and starve without one. Whatever dies becomes Litter, which rots into fertile Soil that speeds nearby growth and holds a seed bank. Sand is what soil becomes once it is lost. Fire is the disturbance that resets it all.

Soil is something the plants build and keep. Only bare, exposed ground weathers back to sand — living roots pin the soil they grow in, and buried soil is shielded by whatever lies above it, so an abandoned slope sheds one thin sand crust and then stops. Plants also work organic matter into the sand they stand in, turning it back into soil. So vegetated land gains soil while stripped land loses it, and a bare dune that plants manage to colonise will slowly green itself. Strip a hillside and you really will lose the topsoil.

The loop. spring → water → plant → grazer → predator → (death) → litter → soil → plant. And overhead: water → vapor → rain. Nothing is a dead end: matter keeps cycling, and the chart under the canvas tracks the three living populations — watch grazers and predators rise and fall in waves.

Fire is ecological, not just pretty. How well a plant catches depends on how dry it is, so parched inland scrub goes up while lush riverbank growth barely burns — and water is a firebreak (a quenched flame flashes to steam). Animals mostly flee the flames; the ones that don't become litter. Everything burnt leaves ash, which rots into soil, so the land comes back greener than it was.

Tuning it. You do not have to write code to change how this world behaves. Pick any living element and the tuning sliders appear beside its rule: a plant's growth rate, thirst, crowding limit and flammability; a grazer's metabolism, appetite, breeding rate and wariness; a predator's hunting skill, stalking range and how much better it does against weak prey; how fast litter rots and what fraction returns as soil or water. Drag one and the next tick already behaves differently — nothing is recompiled, so you can steer a running world. The code editor is still there underneath for anything the sliders do not cover.

Things to try: drag a predator's hunting skill up and watch the herds crash, then collapse · light a fire in dry scrub far from water and watch it stop at the green shoreline · burn a patch and wait for the richer regrowth · drop a predator into a fat herd and watch them scatter · dam a channel with rock to steer where life can grow · crank up evaporation and watch the lake move into the sky · erase a swathe of plants and watch the exposed soil crust over into sand · paint plants onto bare sand and watch them build soil · edit Grazer so it eats Litter too (a scavenger).

Engine notes: cells update bottom-up with an alternating scan direction and a clock bit so nothing moves twice per tick — the same trick sandspiel uses. This is a single static file with zero dependencies: save the page and it keeps working offline.

api reference — how rules work

the model

The world is a grid. Every cell holds a species id plus two bytes: ra (random at birth — used for color texture, or anything you like) and rb (a free register, starts at 0 — commonly a life counter). Each tick, every non-empty cell runs its element's update(api) once. x grows right, y grows down. All offsets (dx,dy) are relative to the current cell. Reads off the grid edge return ROCK.

read

api.get(dx,dy) → species id of a neighbor · api.getRa(dx,dy), api.getRb(dx,dy) → its registers · api.me → my species · api.ra, api.rb → my registers (assignable: api.rb = 40) · api.x, api.y → my position.

write

api.set(dx,dy,id,{ra,rb}?) → overwrite a cell (new random ra, rb 0 unless given) · api.move(dx,dy) → move me there (overwrites target, leaves empty behind) · api.swap(dx,dy) → exchange me with target. move/swap return true and keep following your cell — usually you want to return right after.

randomness

api.randDir() → -1 or 1 · api.rand(n) → integer 0..n-1 · api.chance(p) → true with probability p.

query other elements

api.isLiquid(id), api.isGas(id), api.isPowder(id) · api.densityOf(id) · api.flammabilityOf(id) · api.nameOf(id) · api.prop(id,'anyKey') reads any field off another element's definition — add your own fields and rules can react to them. (Fire does exactly this: it reads Plant's custom burnDry field, then scales it by how dry that plant is.)

sliders (no code needed)

Any numeric field can become a slider. Declare it, then list it in a tune block, and read it back inside update as this.<name>:

speed: 0.4,
tune: { speed: { min: 0, max: 1, step: 0.05, label: "fall speed" } },
update(api) { if (api.chance(this.speed)) api.move(0, 1); }

The panel above builds sliders from that block, and moving one takes effect on the next tick — no recompiling. Use a method (update(api) {…}), not an arrow function, or this will not be your element. Slider positions survive edits elsewhere.

element definition fields

name (also becomes the ALL_CAPS constant other rules use) · color "#rrggbb" · vary 0..1 color grain · liquid/gas/powder flags · density number · flammable 0..1 (chance per tick a neighboring flame ignites it) · paintRb starting rb for brush-painted cells (default 0) · group "water" or "life": which palette row the chip joins (anything else is matter) · tune slider definitions (see above) · update(api) behavior, optional · shade(ra,rb,frame,out) optional dynamic color: fill and return out=[r,g,b] · plus any custom keys you invent.

tips

• return after a move/swap.
• rb === 0 is a handy "just born" signal (see Fire) — or use rb as a resource tank: Plant's stored moisture, or an animal's energy (eat to fill, burn to live, split to breed, die at zero). Use paintRb so brush-placed cells start stocked.
• keep updates small: they run for every cell of that element, every tick.
• a runtime error pauses that element's rule (chip turns red) until you apply a fix.
